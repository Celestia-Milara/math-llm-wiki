# 考研数学提分系统架构优化 v2.0 - 设计文档

## 1. 动机与目标

### 1.1 背景

当前 Vault 已基于 `00_Raw/Archive/` 的 24 讲《张宇 30 讲》内容编译出 56 个 Concepts、37 个 Theorems、54 个 Methods。随着内容量增长，原始架构（v1）暴露出以下问题：

- **00_Raw 扁平存放**：Lectures 和 Problems 混在一起，AI 编译时无法区分处理策略
- **缺少"为什么"层**：只有定义（Concepts）和结论（Theorems）和做法（Methods），没有推导链追踪逻辑演变
- **题目管理空白**：无系统化方式跟踪题目状态和错因
- **Methods 置信体系错位**：三级置信度（待编译→已建立心智模型→已练习验证）适用于理解深度衡量，不适合方法执行准确性的标记
- **02_Output 无标准化产出**：没有定期刷新弱点报告和复习清单

### 1.2 目标

- 优化目录结构，明确各层职责
- 新增 Chains（推导链）和 Records（题目索引库）
- 重新设计 Methods 的熟练度标记体系
- 标准化 frontmatter，确保 Dataview 可查询
- 保留经验证的 v1 设计：概念/定理的置信度三级体系、AI callout 纠偏、Dataview 自动关联

## 2. 目录结构（最终版）

```
.
├── 00_Raw/                         # 原始素材层（只读燃料）
│   ├── Lectures/                   # 《30讲》等教材 Markdown 全文
│   ├── Problems/                   # 《1000题》题干及解析 Markdown
│   ├── images/                     # 原始图片素材（小写）
│   └── Archive/                    # 已处理素材归档区
│       ├── Lectures/               # 已归档的讲次
│       └── Problems/               # 已归档的题目
├── 01_Wiki/                        # 结构化知识层（核心引擎）
│   ├── Concepts/                   # 概念库：定义、核心思想
│   ├── Theorems/                   # 定理库：性质、推论
│   ├── Chains/                     # 推导链：逻辑演变过程（Why）
│   ├── Methods/                    # 方法库：解题 SOP（How / 提分核心）
│   ├── Records/                    # 题目索引库：题目履历与问题状态
│   └── MOC/                       # 章节级 Map of Content 索引页
├── 02_Output/                      # 仪表盘层（数据输出）
│   ├── 弱点报告.md                  # 弱点诊断报告（自动生成）
│   └── 复习清单.md                  # 当前问题方法清单
├── 03_Daily/                       # 指令层（交互中心）
│   └── YYYY-MM-DD.md               # 每日学习日志
├── 04_Templates/                   # 规范层（frontmatter 契约）
│   ├── 概念模板.md
│   ├── 定理模板.md
│   ├── 方法模板.md
│   ├── 推导链模板.md
│   ├── 题目记录模板.md
│   └── 日记模板.md
├── CLAUDE.md                       # AI 管理员手册
└── SCHEMA.md                       # 格式规范
```

### 主要变更

| 对比 v1 | 说明 |
|---|---|
| `00_Raw/` 新增 `Lectures/` + `Problems/` 子目录 | 区分教材与习题，AI 编译时触发不同处理策略 |
| `images/` 统一小写 | 避免跨平台大小写问题 |
| `01_Wiki/` 新增 `Chains/` | 补充"为什么"层 |
| `01_Wiki/` 新增 `Records/` | 题目索引库，命名避免与 Raw 层 `Problems/` 冲突 |
| `01_Wiki/` 新增 `MOC/` | 章节级入口页面，统领各章知识点 |
| `02_Output/` 标准化 | 两份固定产出：弱点报告 + 复习清单 |
| `04_Templates/` 全中文命名 | 与 Obsidian 生态一致 |
| `Archive/` 下分 `Lectures/` + `Problems/` | 与 Raw 层结构对称，便于回溯 |

## 3. Frontmatter Schema（全字段中文）

### 3.1 Concepts（保留三级置信体系）

```yaml
---
标题: 极限
标签: [数学, 微积分, 概念]
创建日期: 2026-05-04
类型: 永久笔记
掌握状态: 待编译              # 待编译 | 已建立心智模型 | 已练习验证
摘要: 描述函数在自变量趋近某值时的变化趋势
---
```

### 3.2 Theorems（保留三级置信体系）

```yaml
---
标题: 格林公式
标签: [数学, 多元函数积分学, 定理]
创建日期: 2026-05-04
类型: 永久笔记
掌握状态: 待编译              # 待编译 | 已建立心智模型 | 已练习验证
摘要: 描述闭区域上二重积分与边界曲线积分的关系
---
```

### 3.3 Methods（改用 issue 标记体系）

```yaml
---
标题: 分部积分法
标签: [数学, 微积分, 方法]
创建日期: 2026-05-04
类型: 永久笔记
问题类型: null                # null | 用不来 | 易混淆
问题备注: "和分部积分法证明不等式混用，不知道什么时候该停"
最后练习: 2026-05-01
摘要: 适用于两类不同函数乘积的积分
---
```

### 3.4 Chains（新增，有创建门槛）

```yaml
---
标题: 从格林公式到曲线积分与路径无关
标签: [数学, 多元函数积分学, 推导链]
创建日期: 2026-05-04
类型: 永久笔记
掌握状态: 待编译              # 待编译 | 已建立心智模型 | 已练习验证
前置知识: ["[[Concepts/格林公式]]", "[[Concepts/曲线积分]]"]
摘要: 理解格林公式如何导出路径无关条件
---
```

创建门槛（三者至少满足其一）：
1. 推导过程在考试中经常作为中间步骤出现
2. 涉及跨章节知识串联
3. 有多个等价推导路径可选

### 3.5 Records（新增，题目电子病历）

```yaml
---
标题: 第8讲-例8.5
标签: [数学, 微积分, 题目记录]
创建日期: 2026-05-04
类型: 永久笔记
来源: "[[00_Raw/Problems/08_第8讲_习题.md#例8.5]]"
题目状态: 未做                # 未做 | 首次做错 | 已纠正 | 熟练 | 掌握
错因类型: null               # null | 计算错误 | 概念不清 | 方法选择错误 | 审题失误
关联方法: ["[[Methods/分部积分法]]"]
---
```

- 不重复存储题干
- 题目状态与 Methods 的掌握状态分离，独立追踪

### 3.6 Daily（保持原有格式）

```yaml
---
标题: 2026-05-05
标签: [日记, 学习日志]
创建日期: 2026-05-05
类型: 日记
---
```

## 4. 核心约束（规范统一性）

### 4.1 所有 Wiki 页面必须包含的字段

| 字段 | 是否必需 | 备注 |
|---|---|---|
| `标题` | 是 | 页面标题，中英文均可 |
| `标签` | 是 | 至少包含 `数学` 和类型标签（`概念`/`定理`/`方法`/`推导链`/`题目记录`） |
| `创建日期` | 是 | 首次创建日期 |
| `类型` | 是 | 固定为 `永久笔记` 或 `日记` |
| `摘要` | 是 | 一句话描述核心内容 |

### 4.2 类型标签统一（`标签` 字段的第三项）

| 页面类型 | 标签值 |
|---|---|
| Concepts | `概念` |
| Theorems | `定理` |
| Methods | `方法` |
| Chains | `推导链` |
| Records | `题目记录` |

### 4.3 各类型特有字段清单

| 页面类型 | 特有字段 |
|---|---|
| Concepts / Theorems | `掌握状态` |
| Methods | `问题类型`、`问题备注`、`最后练习` |
| Chains | `掌握状态`、`前置知识` |
| Records | `来源`、`题目状态`、`错因类型`、`关联方法` |

### 4.4 LaTeX 规范

- 所有数学公式必须使用 LaTeX 渲染
- 多行推导强制使用 `aligned` 环境，每步配 `\text{}` 注释
- 与 v1 保持一致，不作改动

### 4.5 AI 纠偏机制

- AI 生成内容默认包裹 `> [!WARNING] AI 生成` callout 块
- 用户校核后手动移除 callout
- 所有页面类型均适用，与掌握状态无关

### 4.6 双向追溯

- 页面末尾标注来源：`来源：[[]]`
- 归档时在原 Raw 文件 frontmatter 中写入 `处理日期` 和 `维基链接`

## 5. 运行流程

### 5.1 原始素材归档流

```
用户放入 00_Raw/Lectures/ 或 00_Raw/Problems/
    → AI 读取
    → 提取原子笔记写入 01_Wiki/（Concepts / Theorems / Methods / Chains）
    → 原文件添加 处理日期 + 维基链接
    → 移入 00_Raw/Archive/Lectures/ 或 00_Raw/Archive/Problems/
```

### 5.2 日记驱动分析流

```
用户在日记中标记 - [!] [[Records/第8讲-例8.5]] 并写下错因
    → AI 检索 00_Raw/Problems/ 中对应解析
    → 更新 Records/ 的 题目状态 + 错因类型
    → 更新关联 Methods/ 的 问题类型 + 最后练习
    → 刷新 02_Output/ 下的两份报告
```

### 5.3 弱点报告刷新流

```
AI 在用户指令或日记触发下：
    → 查询 Methods 中 问题类型 != null 的条目 → 写入 复习清单.md
    → 聚合 Records/ 中的 错因类型 分布 → 写入 弱点报告.md
```

## 6. Dataview 查询规范

### 6.1 弱点清单（02_Output/复习清单.md）

```dataview
TABLE 问题类型 AS 问题, 问题备注 AS 备注, 最后练习 AS 最后练习日期, 摘要 AS 方法概述
FROM "01_Wiki/Methods"
WHERE 问题类型 != null
SORT 最后练习 ASC
```

### 6.2 方法关联题记录（Methods 页面底部）

```dataview
TABLE 题目状态 AS 状态, 错因类型 AS 错因, 来源 AS 题目来源
FROM "01_Wiki/Records"
WHERE contains(关联方法, [[当前方法标题]])
SORT 创建日期 DESC
```

### 6.3 概念/定理关联（Concepts / Theorems 页面底部）

```dataview
TABLE 类型 AS 笔记类型, 掌握状态 AS 状态
FROM "01_Wiki"
WHERE 类型 = "方法" OR 类型 = "定理"
WHERE contains(标签, "当前章节标签")
```

## 7. 关键设计决策记录

| 决策 | 选择 | 理由 |
|---|---|---|
| Records/ 命名而非 Problems/ | 避免与 00_Raw/Problems/ 命名冲突 | `[[wikilink]]` 歧义 |
| Methods 改用问题类型标记 | 方法掌握程度是"有无问题"而非"理不理解" | 对齐真实需求 |
| Concepts/Theorems 保留三级掌握状态 | 概念/定理存在理解深度递进 | 已验证有效 |
| AI callout 保留在所有页面 | 内容来源可信度与掌握程度正交 | 幻觉防护 |
| images 统一小写 | 跨平台兼容 | Windows 不敏感但 macOS/Linux 敏感 |
| Chains/ 有创建门槛 | 防止每个定理都建链造成冗余 | 只有跨章节或多路径推导才创建 |
| Frontmatter 全中文化 | 降低认知负担，避免中英混用 | 用户要求 |

## 8. 未纳入范围（后续考虑）

- 真题套卷（00_Raw/Exams/）— 暂不引入，等当前系统稳定后再评估
- 自动复习排程 — 用户明确不需要
- 章节进度统计看板 — 可后续用 Dataview 或 Obsidian Bases 实现，不影响架构
